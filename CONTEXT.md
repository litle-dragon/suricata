# Suricata Alert Bridge

Домашня IDS: Suricata (пасивний мітчинг WAN-трафіку через MikroTik) генерує алерти в `eve.json`; `alert-bridge.py` (демон) реагує на них — блокує атакуючих на MikroTik і шле звіти в Telegram. Допоміжні CLI-скрипти (`analyze_stats.py` та інші) працюють поверх тієї самої SQLite-бази.

## Language

**Демон** (alert-bridge):
Єдиний довгоживучий процес (`alert-bridge.py`, systemd-сервіс), який `tail -F`-ить `eve.json`, приймає рішення про блокування на MikroTik і формує звіти. Синглтон — усе інше (`analyze_stats.py` тощо) працює поверх тієї самої SQLite-бази, але не є демоном.

**Тимчасовий блок**:
Запис у MikroTik address-list з `timeout=BLOCK_TIMEOUT` (типово 1h) — самостійно спадає. Застосовується до inbound-спроб 1–2 і завжди для outbound.
_Avoid_: temporary ban

**Постійний блок**:
Запис у MikroTik address-list без timeout, з коментарем `PERMANENT: ...`, назавжди. Кожен постійний блок аудиться в таблиці `permanent_blocks` (`ip_or_subnet`, `kind`, `signature`, `blocked_at`) і кешується в пам'яті (`_permanently_blocked_ips`/`_permanently_blocked_subnets`), щоб не переопитувати MikroTik на кожен наступний алерт.
_Avoid_: permanent ban

**Спроба** (attempt):
Один inbound-хіт від конкретної IP за поточну добу. На 3-й спробі (`PERMANENT_THRESHOLD`) IP ескалується з тимчасового блоку в постійний.

**Підмережа** (у поточному коді):
Агрегаційний кошик `/24` (IPv4) чи `/64` (IPv6), обчислюваний `get_subnet(ip)` — не довільний CIDR, а завжди фіксованої довжини префікса. Використовується для порогової ескалації (`SUBNET_THRESHOLD` унікальних all-time IP → постійний блок усієї підмережі) і для multi-day override. **Це відмінне поняття від "діапазону"** (див. нижче).

**Діапазон** (range):
Довільний CIDR-запис із зовнішнього блок-листа (geoip.txt/Spamhaus DROP), довжина префікса не фіксована. Демон визначає "охоплюючий діапазон" для алертованої IP власним lookup'ом по локальній копії списку (Suricata IP Reputation/`iprep` підтверджує лише категорію й score для IP, не яка конкретна CIDR-адреса зі списку збіглася — ADR-0003). Область застосування — **лише IPv4**; IPv6 свідомо не підтримується для geo/Spamhaus-блокування.
_Avoid_: підмережа (зайнято іншим значенням), CIDR-блок

**Вайтлист**:
Множина адрес, які демон ніколи не блокує і не рахує: RFC1918/CGNAT/loopback, публічні DNS-резолвери (Cloudflare/Google/Quad9/OpenDNS/AdGuard), власні WAN-адреси. Захист від самоблокування.

**HOME_NETS** (у демоні):
Список власних мереж (RFC1918 + CGNAT + власні WAN IP/IPv6-префікси з `.env`), який `classify_flow()` використовує лише для визначення напрямку (inbound/outbound) алерту. Незалежна від Suricata-конфігураційного `HOME_NET` у `suricata.yaml` (та сама ідея, два окремі визначення, які потрібно тримати синхронізованими вручну).

**Напрямок** (inbound / outbound):
inbound — джерело поза HOME_NETS, ціль усередині (щось іззовні атакує LAN/WAN IP); outbound — навпаки (щось із LAN атакує/стукає назовні). Визначає різні гілки логіки блокування (inbound має ескалацію 1→2→3, outbound — завжди лише тимчасовий блок).

**Дайджест** vs **Звіт**:
Дайджест — підсумок за слот (6 год); звіт — підсумок за повну добу, надсилається о 07:00 і читає вчорашній архівний рядок з `daily_stats` (не рахує наліво з пам'яті процесу).

**Аномальний сплеск (spike)**:
Подія, коли кількість inbound-алертів у ковзному 5-хвилинному вікні (`SLIDING_WINDOW`) перетинає `SPIKE_THRESHOLD_N` — єдина подія, що пейджить у Telegram у реальному часі; не впливає на рішення про блокування (воно йде окремим шляхом).

**Категорія алерту** (нова):
`geo-<CC>` (`geo-ru`/`geo-by`/`geo-cn`/`geo-kp`/`geo-ir`) чи `spamhaus` — записується як `kind` у `permanent_blocks`, той самий audit-механізм і кеш, що й для звичайних постійних блоків, але власний, паралельний конвеєр обробки: блок одразу на першому алерті (без спроб/ескалації/cooldown), не проходить через `record_hit()`/`seen_ips` uniqueness. На MikroTik групується по 2 списках за категорією (`suricata-geo-block` — усі 5 країн разом, `suricata-spamhaus-block` — окремо), не по країні; розбивка по країні лишається в звітах і `analyze_stats.py`.
